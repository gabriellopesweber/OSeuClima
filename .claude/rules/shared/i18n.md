# Regras de i18n

> **Escopo:** vale apenas para projetos que já usam **vue-i18n**. Num projeto sem i18n, a proibição de "string hardcoded" **não se aplica** — texto direto no template é o correto ali. Não instale vue-i18n nem crie `src/locales/` por conta própria: internacionalizar é decisão de produto, com custo de manutenção permanente. Se o projeto pode vir a precisar, proponha; não execute.
>
> **Idiomas, árvore de arquivos e namespaces deste projeto:** `.claude/rules/project/stack.md`.

## Estrutura de arquivos

Um arquivo por feature, agrupado por namespace, dentro do diretório do idioma:

```
src/locales/{locale}/
├── common.json          # ações genéricas: cancel, confirm, save, close, loading…
├── auth.json
├── validation.json
└── {namespace}/
    └── {feature}.json
```

Todos os arquivos são deep-merged pelo plugin de i18n via `import.meta.glob('**/*.json')` — não há registro manual: criar o arquivo já o carrega.

## Estrutura JSON obrigatória
Todo arquivo deve envolver as chaves no seu namespace:
```json
{ "workspace": { "invites": { "title": "Convidar Membro" } } }
```
Nunca colocar chaves soltas na raiz do arquivo.

## Nomenclatura de chaves
- `common.{chave}` — ações globais reutilizáveis
- `{namespace}.{feature}.{chave}` — chave específica de feature
- `{namespace}.{feature}.{categoria}.{chave}` — para grupos: `errors`, `success`, `headers`, `stats`, `actions`
- Formato: `snake_case`, sem camelCase

## Fluxo para adicionar texto novo
1. Verificar `common.json` — cancel/confirm/save/close/loading e afins já existem
2. Identificar o arquivo correto (namespace + feature)
3. Adicionar na posição lógica dentro do JSON existente
4. **Se o projeto tem mais de um idioma, adicionar em todos simultaneamente** — chave faltando num locale é bug de produção
5. Usar no template: `{{ t('chave') }}` ou `:label="t('chave')"`

## Interpolação e pluralização
```json
{ "workspace": { "employees": { "remove_msg": "Remover {name} do workspace?" } } }
```
```js
t('workspace.employees.remove_msg', { name: member.firstName })
```
Para slots nomeados em HTML: usar `<i18n-t keypath="..."><template #name>…</template></i18n-t>`

## Proibições
- **Strings hardcoded em templates** (mesmo que "temporariamente")
- Chaves de feature dentro de `common.json` — `common` é só o que é genuinamente global
- Chaves duplicadas que já existem em outro arquivo do mesmo namespace
- **Expor enum/termo cru em inglês ao usuário** (ex.: status `PAID`, `PENDING`) — todo texto visível vai no idioma da UI. Sempre traduzir o enum/valor técnico reusando a chave de status existente; vale inclusive dentro de frases já traduzidas.
- Concatenar strings traduzidas para montar frase — usar interpolação, senão quebra em outros idiomas
